# CLAUDE.md — SkyGlance MCP

## What This Is

An MCP server that answers questions about aircraft: what's overhead right now and where
to look, what a given plane is, where a flight is, and what has passed over before.
24 tools, free data, no API keys.

Sibling project: [skyglance-mac](https://github.com/darshjoshi/skyglance-mac) — same data,
macOS menu bar app. **Its `docs/` are the research this is built on** and are worth
reading before changing anything here: `FREE-STACK.md`, `OVERHEAD-DETECTION.md`,
`COVERAGE-AND-COST.md`.

## Architecture

- `src/skyglance/server.py` — MCP tool definitions. Thin: validate, delegate, format.
- `src/skyglance/feeds.py` — three ADS-B feeds queried in parallel and merged. Circuit
  breakers, rate-slot reservation, coordinate coarsening, last-good snapshot.
- `src/skyglance/geometry.py` — elevation, bearing, slant range, closest point of approach.
- `src/skyglance/enrich.py` — adsbdb → hexdb → planespotters, cached forever.
- `src/skyglance/interest.py` — scoring: which aircraft is worth mentioning.
- `src/skyglance/weather.py` — Open-Meteo, the "can you actually see it" gate.
- `src/skyglance/store.py` — SQLite history: aircraft, passes, enrichment cache.
- `src/skyglance/poller.py` — background poller + single-instance lock.
- `src/skyglance/traces.py` — ~24h flight paths from `globe.adsb.lol/data/traces`.
  **Reduction is the whole job here**: a raw trace is ~2,600 points / 450 KB, which is
  unusable in a context window. It gets segmented into legs and downsampled to
  `PATH_SAMPLES` points each. Don't raise that without checking the output size.
- `src/skyglance/airports.py` — ICAO lookup plus observed departing/arriving/on-ground
  classification by climb rate. Airport records are cached forever; airports don't move.
- `src/skyglance/airport_data.py` — ~1,150 major airports embedded from OurAirports
  (public domain). Generated by `tools/build_airports.py`; don't hand-edit.
- `src/skyglance/world.py` — the global sweep. adsb.lol's point query has no radius cap,
  so a 12,000 nm radius returns ~6,000 aircraft worldwide in ~1.3s. That single response
  is ~3.7 MB from volunteers, so it is fetched **at most once per 60 seconds**,
  process-wide, shared between concurrent callers, and served from cache in between.
  Never call it to answer something a 60 nm circle can answer.

## Rules That Are Load-Bearing

**`mcp>=1.0.0,<2` — do not loosen.** MCP Python SDK 2.0 removed `mcp.server.fastmcp`,
which every tool here is built on. The sibling project pitwall shipped `mcp>=1.0.0` and
every new install broke the day 2.0 was published. Lifting the bound means porting all 24
tools to `mcp.server.mcpserver.MCPServer` first. Same reasoning for `httpx<1`.

**stdout is the JSON-RPC channel in stdio mode.** Every diagnostic goes to `sys.stderr`,
via `logging` (already configured to stderr in `server.py`). A stray `print()` corrupts
the protocol stream.

**Coordinates are coarsened in `feeds.coarsen`, at URL-build time.** Not by callers. This
keeps the guarantee that no code path reaches a feed with an exact position, and
`tests/test_feeds.py::TestPrivacy` fails if a new source is added that skips it.

**Identifiers are validated before entering a URL path.** `../../v0/aircraft/x` as a
callsign walks the URL to a different endpoint, and `?`/`#` rewrite the request. Both were
verified exploitable against the original Swift implementation.

**Never predict beyond `PREDICTION_HORIZON_S` (90s).** Measured straight-line error is
0.11 km at 30s but a median 5.98 km at 240s. `coming_overhead` splits its output so the
model cannot invent a countdown; don't "improve" this by extrapolating further.

**OpenSky stays out.** It adds ~10% coverage but its licence requires a written agreement
for operational use, and this package is redistributed.

## Data Sources

All free, no API keys. Terms and obligations in `NOTICE.md` — attribution is returned in
the tool output because ODbL and planespotters require it.

- Positions: adsb.lol (ODbL), airplanes.live, adsb.fi — merged, ~17% more aircraft than
  the best single source (measured Newark 2026-08-02: union 61 vs best 52)
- Identity: adsbdb.com → hexdb.io fallback · Photos: planespotters.net
- Conditions: Open-Meteo
- Global endpoints on adsb.lol: `/v2/mil`, `/v2/squawk/X`, `/v2/type/X`,
  `/v2/registration/X`, `/v2/callsign/X`

## Testing

```bash
uv venv && uv pip install -e ".[dev]"
pytest
```

`tests/test_geometry.py` asserts **exact-digit parity** with `reference/overhead.mjs` from
the Mac app on three values. If the port ever drifts, those fail first. Re-derive expected
values by running that file rather than by hand.

## Releasing

Bump the version in **four** places or the release is broken:

1. `pyproject.toml` → `version`
2. `server.json` → `version` **and** `packages[0].version` (the registry rejects a
   mismatch with PyPI)
3. `plugins/skyglance/.claude-plugin/plugin.json` → `version`
4. `.claude-plugin/marketplace.json` → `plugins[0].version`

Then publish a GitHub release; `.github/workflows/publish.yml` handles PyPI (trusted
publishing) and the MCP registry.

**Never republish a changed build under an existing version.** `uvx` caches its
environment by package version, so users who already ran that version keep executing the
old code — silently, with no error. Verified during development: a rebuilt `0.1.0` wheel
containing four new tools still served the old sixteen through `uvx`, and `--refresh` did
not clear it, while a fresh venv from the same wheel served all twenty. Bump the version
for every change that ships.

When testing local changes, install into a venv and run that binary directly. Testing
through `uvx` against a rebuilt same-version wheel gives false negatives.
